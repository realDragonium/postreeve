# Design

## Context

`App.tsx` owns one `keydown` listener on `document`. The reader and list are flex panes inside `.mail-view`; `styles.css` has one `max-width: 900px` block. The server serves `dist/` with a CSP of `default-src 'self'; img-src 'self' data: blob: http: https:; script-src 'self'; connect-src 'self'; frame-src 'none'`. That file belongs to the parallel auth branch, so this change avoids touching it.

## Decisions

1. **Typing detection is a pure function** (`isTypingTarget` in `src/web/keyboard.ts`): true for `INPUT`, `TEXTAREA`, `SELECT`, any element whose `isContentEditable` is true, and anything inside `[role="textbox"]` or `[contenteditable]`. The handler returns before the Cmd/Ctrl+Z branch, so editor undo is never hijacked. Escape still blurs. A pure function is unit-testable without a DOM and the e2e test covers the real editor.
2. **Dialogs swallow single-key shortcuts.** The old guard only skipped mailbox shortcuts while an overlay was open, but `[` and Cmd+Z still fired. Now, with any overlay or the help overlay open, only Escape (close help) is handled. Cmd/Ctrl+Z with an overlay open does nothing, since the person is in a dialog, not the mailbox.
3. **Shortcuts follow Gmail** where Postreeve has the action: `r`, `a`, `f`, `c`, `#`, `g i`/`g s`/`g d`/`g t`, `?`. `Shift+U` marks the target unread (Gmail's mark-unread); `u` keeps its existing toggle. `g` starts a 1.5 s chord. Go-to resolves against the current scope: an account scope goes to that account's folder with the special use; a unified scope switches the unified special use, which already covers Drafts and Trash. Reply/forward need the full message detail, which `Reader` loads; `App` reads it from the query cache (`["message", key, ref]`) and fetches it if absent, so the shortcut works from the list too.
4. **Error boundary** is one class component with a `fallback` render prop and a `resetKeys` array. The shell boundary sits in `main.tsx` around `App`; pane boundaries wrap `Reader` (reset on open key) and `ComposeModal` (reset on overlay). The message is shown as React text, never HTML. No error reporting service: Postreeve is local-first and has none.
5. **Phone layout at 640 px, tablet keeps 900 px.** 390 px phones need different rules from a 768 px tablet; the existing 900 px rules (sidebar overlays, list hides under reader) stay, and a new 640 px block adds full-screen compose and sheets, 44 px rows and buttons (`pointer: coarse` also raises targets on touch tablets), a sticky reader toolbar that scrolls horizontally instead of wrapping into five rows, and `env(safe-area-inset-*)` padding (`viewport-fit=cover`). On phones the top bar wraps to two rows (menu, brand and tabs; then a full-width search) instead of moving the tabs into the sidebar, which keeps `Sidebar.tsx` untouched. The browser back button closes the reader through a `popstate` history entry, because phone users expect the system back gesture to return to the list.
6. **Service worker scope is the shell only.** `public/sw.js` handles same-origin `GET` requests outside `/api/`: navigations are network-first with the cached `/` as offline fallback, `/assets/*` (content-hashed) are cache-first, other static files network-first. Responses with `Cache-Control: no-store`, non-200 or non-basic responses are not cached. Activation deletes other `postreeve-shell-*` caches. Registration happens only when `import.meta.env.PROD`, the protocol is `http:` or `https:`, and `serviceWorker` exists, so neither the Vite dev server (and the e2e suite) nor the Electron `postreeve:` protocol gets one. `worker-src` and `manifest-src` fall back to `default-src 'self'`, so the current CSP already allows both: **no CSP edit**.
7. **Icons** are a flat red square with a white `P` mark in the existing accent, rendered from one SVG to 192, 512, maskable 512 and 180 px (Apple touch) PNGs and committed. iOS needs `apple-mobile-web-app-capable` and the touch icon; Android needs the manifest.
8. **Attachment preview avoids frames.** `frame-src 'none'` blocks a `blob:` PDF in an iframe, and loosening it is the auth branch's file. Images render as `<img src=blob:>`, which `img-src blob:` allows. The blob is re-created with the declared media type only when it is on an allowlist of raster types; SVG is excluded because opening it top-level would run script. PDFs open in a new tab from a `blob:` URL typed `application/pdf`; the tab is opened synchronously on click (so mobile popup blockers allow it) and navigated once the bytes arrive, with `opener` cleared. Images load automatically up to 10 MB each and 8 per message; larger ones get a **Preview** button. Object URLs are revoked on unmount.
9. **Brand typo** fixed in the top bar; the CSS comment that names the design file keeps its original name.

## Risks

- A stale cached shell after a deploy: navigations are network-first, so a reachable server always serves the new `index.html`, which names new hashed assets.
- A `blob:` PDF tab shares the app origin. The type is forced to `application/pdf`, which browsers render in their PDF viewer rather than as HTML.
